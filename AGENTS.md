## Current architecture
- Eleventy is a build-time tool only. The deployment is static HTML, local CSS, fonts, images and a PDF. No Wix site runtime, CMS account, database or app server is required.
- Existing pages and articles retain their original styled HTML in `content/pages/**/*.njk`, `content/posts/*.njk`, `content/archives/*.njk` and `content/blog.njk`. Use these as the authoritative content; the earlier Markdown conversions were replaced.
- Original mobile layouts are in `templates/original/*.mobile.html`. **An existing-page edit must also update its mobile counterpart.** A small local script selects the original layout and handles menus, sharing and honest preview-only form feedback.
- `templates/exact-base.njk` provides metadata, local styles and layout selection. Shared original desktop header/footer are in `templates/original/`. Mobile header/footer are also reusable. The original floating phone widget templates are archived but no longer included; its popup handlers and widget/icon styles must not be loaded again.
- `public/assets/fidelity.css` contains the approved picture rounding, animation removal and static layout adapters. Do not reintroduce the rejected `site.css` design.
- Original CSS styling identifiers are retained to preserve layout; their presence does not mean the Wix JavaScript runtime is retained.
- Preserve Ricos presentation attributes such as `data-breakout`, `data-ricos-font` and `data-list-style`. Removing them widened article text from 740px to 938px even though fonts and words still passed checks. The Ricos gap-spacer rule also loads after the initial server CSS and is retained in `fidelity.css`. Check inner paragraph/list/image boxes and line wrapping, not only component IDs.
- `public/assets/original/` holds the actual source crops and fonts. Some PNGs were losslessly converted to WebP; `migration/reference/lossless-assets.json` records the path mapping. `asset-aliases.json` records image deduplication and filenames corrected to the downloaded format. Do not apply lossy image changes during fidelity work.
- **Wix SSR background images may be tiny loading thumbnails.** The mobile cabinet photo was an 80×77 placeholder stretched to 320×306. Removing `blur_*` from its URL did not restore its resolution. When `data-image-info.isLQIP` is true, use the original media URI, target size and crop to obtain full-resolution images. Preserve/localize `srcset` through repeated serialization. The cabinet photo now has local 320×306, 640×612 and 960×918 variants for 1x/2x/3x displays (`cabinet-mobile-assets.json`). The CDN's `enc_avif` URLs can return JPEG bytes; preserve the delivered pixels and use the correct file extension.
- **All site assets must be local**, including images, video, fonts, CSS, icons, PDF files, responsive variants, social-preview images and structured-data media. Do not link assets to Wix/CDNs or freeze remote URLs in embeds. The owner explicitly approved **interactive Google Maps** as the sole external asset-service exception. Its two local iframe wrappers now load Google directly; the previous Wix renderer, icon and map transport were removed. Google's standard map UI replaces the former Wix-customized styling.
- The asset audit in `scripts/check_assets.py` runs with `npm run check`: it inspects every deployable HTML/SVG/CSS/JS/JSON/XML file, including nested local embeds and metadata. It rejects Wix URLs, hotlinked resources and missing local files. Outbound navigation links, canonical identities and schema namespaces are not asset loads. Archived provenance under `migration/` may retain original URLs and must never be deployed.
- Metadata media paths are local in the sources. The metadata filter uses localhost during `--serve` and the site's own origin in production, so Open Graph and JSON-LD media URLs are absolute while referring to files deployed with the site.
